## Analisi Performance — Problemi e Cause

### 🔴 Problema 1: TBT 2,160ms (score 0.06) — Il killer principale

| Cosa consuma | Tempo |
|---|---|
| Script Evaluation | 2.5s |
| Style & Layout | 0.4s |
| Script Parsing & Compilation | 0.15s |
| **Totale main thread** | **5.9s** |

**Causa**: 511KB di JS (index.js 320KB + TodoPage.js 191KB) parsificati su CPU 4x slowdown. Con 704 task totali, di cui 14 long task (>50ms), il thread principale è bloccato per 2.1s.

**Long task più lunghi**:
| Durata | Fonte |
|---|---|
| **866ms** | Unattributable (framework core) |
| **601ms** | `app/todo` (TodoPage mount) |
| **434ms** | `app/todo` (router init + app bootstrap) |
| **330ms** | `useGuestMigration-CDhXENtj.js` |
| **311ms** | `app/todo` (template rendering) |
| **291ms** | `matomo.js` (Matomo analytics) |

### 🔴 Problema 2: LCP 4.2s (score 0.43)

**LCP breakdown**:
| Subpart | Durata |
|---|---|
| Time to first byte | 547ms |
| **Resource load delay** | **2,479ms** ← 🎯 target |
| Resource load duration | 389ms |
| Element render delay | 20ms |

Il LCP è un'immagine (`img/icons/icon-128x128.png`, usata come logo). Il carico effettivo è veloce (389ms), ma **la richiesta parte dopo 2.5s** perché il main thread è bloccato dal parsing JS.

### 🟡 Problema 3: Unused JavaScript (91KB sprecati)

| File | Totale | Inutilizzato | % |
|---|---|---|---|
| `index-B_F8545V.js` | 110KB | **50KB** | 45% |
| `TodoPage-BZbjQ7vA.js` | 65KB | **42KB** | 65% |
| **Totale** | **175KB** | **92KB** | 52% |

### 🟡 Problema 4: Legacy JavaScript (19KB)

TodoPage.js contiene polyfills Babel per browser legacy:
- `@babel/plugin-transform-classes`, `transform-spread`
- Polyfills: `Array.from`, `Array.prototype.filter`, `Object.entries`, ecc.

Questi polyfills non sono necessari per browser moderni (Chrome 150+).

### 🟢 Problema 5: Image delivery (22KB)

L'immagine logo `icon-128x128.png` (16KB) è visualizzata a 56x56px, ma caricata a 128x128px. Stesso discorso per `icon-72x72.png` (6KB) visualizzata a 40x40px.

## Opportunità di miglioramento (priorizzate)

### P1 — Impatto alto, effort basso (🎯 DA FARE SUBITO)

| # | Azione | Risparmio stimato | Dove |
|---|---|---|---|
| 1 | **Code splitting più aggressivo**: separare Vue/Vue Router/Drag library dal bundle principale | **TBT -500ms, LCP -1s** | `vite.config.js`: manualChunks |
| 2 | **Defer registerSW.js** aggiungendo `type="module"` o post-loading | Render più veloce | `index.html` riga 58 |
| 3 | **Inline CSS critico** e differire il resto | **FCP -300ms** | Inline o preload |
| 4 | **Aggiungere `fetchpriority="high"` al logo LCP** | **LCP -500ms** | `<img fetchpriority="high">` |
