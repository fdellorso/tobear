# Tobear — Audit Tecnico Completo

**Data audit:** 2026-07-06 · **Auditor:** Technical Lead · **Scope:** `backend/` + `frontend/` + root
**Metodo:** lettura diretta di codice, migrazioni, route, config, handoff, skills, opencode.json, git log. Nessuna modifica eseguita.

---

## 1. Executive Summary

Tobear è una todo-app PWA offline-first in stile Clear, composta da due repo indipendenti gestiti con due sessioni OpenCode separate:

- **Backend** Laravel 12 (PHP 8.4 runtime, ^8.2 contract) + Sanctum SPA cookie-auth + MySQL/SQLite, 11 migrazioni, 67 test, API REST versionate sotto `/api/v1`.
- **Frontend** Vue 3 `<script setup>` + Vite 6 + Tailwind v4 + Pinia (Options) + vue-router 4 + idb + vuedraggable + vite-plugin-pwa + vue-i18n 11, 5 spec E2E Playwright, 28 test Vitest.

Lo stato **ufficiale** (TODO.md + ultimi handoff) indica MVP sostanzialmente completato (CRUD task + reorder + offline + guest mode + migrazione guest→auth + PWA + i18n + temi chiaro/scuro), in fase di **pre-deploy su x10hosting** per validazione PWABuilder.

L'audit rivela tuttavia **problemi critici di sicurezza e di build di produzione** che **impedirebbero un deploy funzionante**:

1. **CRITICO sicurezza backend** — `APP_KEY` committata in 3 file `.env.*` tracciati in git pubblico; `GET /artisan/{cmd}` esposto senza auth (solo token in query string, token stesso committato); `GET /serverphpinfo` senza auth; password DB reale `frisedda` committata.
2. **CRITICO build frontend** — CSP con `laravel.fritz.box:8080/8000` hardcoded finisce nel `dist/index.html` di produzione e **blocca ogni chiamata API** verso `tobear.x10.mx`; `base: '/'` hardcoded ignora `VITE_BASE_URL=/app` rompendo gli asset se serviti da subpath.
3. **ALTO funzionale** — il runtime caching API del service worker è rotto (funzione `urlPattern` serializzata con `env` free variable → `ReferenceError` in `sw.js`); `router.push({ name: 'Home' })` dopo logout punta a una route inesistente (logout UI non naviga).
4. **ALTO documentazione** — AGENTS.md di **entrambi** i repo è ampiamente obsoleto: dice stringhe italiane (migrate a EN + i18n), cita `tailwindplus/` (cancellato), `GuestLayout`/`DefaultLayout`/`HomePage` (cancellati), `PHP 8.2` nell'header vs `8.4.1` nella tabella, porta dev `3000/https` vs reale `3001/http`.

A queste si aggiungono debito tecnico diffuso (N+1 writes in `reorder`, image resize sincrono non in queue, `$request->all()` al posto di `validated()`, 7 commit backend + 4 frontend post-handoff non documentati, ~10 handoff che riportano "test per TaskItem" senza mai chiuderlo).

**Prontezza per la produzione: NON IDONEA** in stato attuale. Richiede almeno: rotazione APP_KEY + untrack `.env.*`, rimozione/guard di `/artisan` e `/serverphpinfo`, fix CSP produzione, fix `base` Vite, fix SW runtime caching, poi validazione E2E su dominio reale.

## 2. Comprensione del Backend

### 2.1 Stack
Laravel 12.15, PHP 8.4.1 (runtime), Sanctum 4 (SPA cookie), Intervention/Image v3 (GD), Breeze scaffolding (auth), MySQL/SQLite, queue=database, cache=database, session=database. Deploy via GitHub Actions → FTP su x10hosting.

### 2.2 Architettura
Pattern a 4 file per risorsa: `Controller (V1/) → FormRequest → Model → Resource (V1/)`. Ownership check centralizzato nel trait `app/Traits/OwnsModel.php` (`authorizeOwnership(Request, Model)` → `abort(403)`). Niente Policy/Gate, niente Jobs/Events/Mail, niente Blade (SPA shell servita da `public/app/index.html`). Solo `AppServiceProvider` registrato; `RouteServiceProvider`/`AuthServiceProvider` assenti (Laravel 12 style in `bootstrap/app.php`).

## 4. Comprensione dell'integrazione Backend ↔ Frontend

Frontend `axiosClient` con `withCredentials: true`, `withXSRFToken: true`. `withCSRF(callback)` helper → `GET /sanctum/csrf-cookie` prima di login/register/logout/password/contact. ### 4.3 Contratto risposta — allineamento
- Backend AGENTS.md:46: "Risposte sempre tramite Resource, frontend si aspetta `response.data.data`"

## 9. Problemi di architettura

1. **Niente Policies/Gates**: ownership check manuale hardcoded su `user_id`. Va bene finché non arrivano ruoli/permessi (TODO.md lo riconosce), ma non generalizza a entità senza `user_id` (ContactMessage) e forza inline check in `ImageManipulationController::resize:57`.
2. **API group con `StartSession` su tutte le route API**: necessario per cookie auth ma overhead (scrive session row per ogni request API). Andrebbe separato stateful da stateless.
3. **Resize immagine sincrono**: blocca PHP-FPM worker; `composer dev` ha `queue:listen` ma resize non dispatchato. Non scala.
4. **Frontend senza store `task`**: stato task locale a `TodoPage.vue` (433 righe) — non riusabile, monolitico, difficile da testare. Limita feature future (liste annidate, grocery).
5. **Router eager import**: nessun code-splitting, tutto in un chunk. Pessimo per first-load mobile 3G.
6. **Layout unico `AppLayout` per guest+auth**: login/register sotto AppLayout → FAB/sidebar sovrappone al form su mobile.
7. **Deploy same-host ambiguo**: backend catch-all serve SPA, frontend CI deploya `dist/` via FTP separata — conflitto o subpath non gestito.
8. **Niente Jobs/Events/Mail**: queue=database ma inutilizzata; notifiche contatto e resize in-process.
9. **`personal_access_tokens` table inutile**: SPA mode non emette token.
